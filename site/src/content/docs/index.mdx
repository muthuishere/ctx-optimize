The agent does not have to understand the repo from scratch every session. The store
already has the **nodes** (files, symbols), the **edges** (contains, imports, calls),
and the **boundaries** (hosts, env names, spawned binaries). It asks the CLI —
`query`, `card`, `change-plan`, `affected`, `boundaries` — and cites a `file:line`.
A small model gets smart because the graph is already there. A big model keeps the
window for the edit, not for rediscovering who talks to what.

On a graded run (gorilla/mux, same model, no LLM judge): **67% correct in 15 tool
calls** against a grep-armed agent's **35% in 43**. That is the overall-session
number — fewer round trips, more of the window left. We do not claim 79× token
savings. We measured that and dropped it.

No database. No server. No model in the gather. **No MCP** — the graph is a folder
and a CLI, so a no-change `sync` is ~0.25s and `card` is milliseconds. A daemon is
the slow path.

## Install

Pick your agent and paste. Three commands.

<Tabs>
<TabItem label="Claude Code">
```text
npm install -g @muthuishere/ctx-optimize
cd your-repo && ctx-optimize up
ctx-optimize install --claude
```
Then: answer code questions with `query`, `card`, `change-plan`, `affected`, `boundaries`.
Cite the `file:line`. Grep stays for exact strings.
</TabItem>
<TabItem label="Codex">
```text
npm install -g @muthuishere/ctx-optimize
cd your-repo && ctx-optimize up
ctx-optimize install --codex
```
Trust the hook once with `/hooks`. Same verbs. Cite the `file:line`.
</TabItem>
<TabItem label="Copilot">
```text
npm install -g @muthuishere/ctx-optimize
cd your-repo && ctx-optimize up
ctx-optimize install --copilot
```
Same verbs. Cite the `file:line`.
</TabItem>
<TabItem label="Any / Grok / Devin">
```text
npm install -g @muthuishere/ctx-optimize
cd your-repo && ctx-optimize up
ctx-optimize install
```
Grok already reads the Claude skill dir. Devin reads `~/.agents/skills`. `init` is only
if you want the committed pointer in the repo.
</TabItem>
</Tabs>

The agent **may still grep**. We do not block it. After you edit, `ctx-optimize sync`.
Lazy autosync is opt-in (`"autosync": "lazy"`), not on. [Walkthrough →](/ctx-optimize/quickstart/)

## Same store, two doors

`change-plan Store.Merge` is the agent door. `ctx-optimize serve` is yours — Flow draws
directories, real call counts, the hub, and the outer world (hosts and env **names**,
never a value).
