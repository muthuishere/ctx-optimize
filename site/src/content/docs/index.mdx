The skill and hook install globally; the agent flag only picks which agent gets wired up. The
optional part is the marker-fenced rule in your global instructions file — that is what makes
an agent reach for the store unprompted, and `uninstall` removes it cleanly. `init` is the only
step that touches the repo, and what it writes is meant to be committed.
[The full walkthrough →](/ctx-optimize/quickstart/)

## What is different

<CardGrid>
	<Card title="Nothing to run">
		One static binary. No database, no daemon, no language server, no model, no MCP.
		The store is sorted newline-delimited JSON you can read with your eyes and diff in
		git.
	</Card>
	<Card title="Deterministic">
		Same input, same graph, byte for byte. The binary makes no LLM call, computes no
		embedding, and holds no credentials at rest. Your agent supplies the intelligence.
	</Card>
	<Card title="Every answer is citable">
		A hit is a resolved symbol with its real `file:line` range, signature and doc — not a
		matching line you still have to chase.
	</Card>
	<Card title="Every edge states its confidence">
		EXTRACTED is parsed fact. INFERRED is name-matched. AMBIGUOUS is surfaced as a
		shortlist rather than guessed into the graph, and filtered out of traversals unless
		you ask for it.
	</Card>
</CardGrid>

And one answer no other tool in our comparison table has: `boundaries` — the repo's external
surface, with direction, transport, and credentials flagged **by name**.

## The evidence, in two rows

One agent, three arms, twelve hand-verified questions on **gorilla/mux**. 3 runs, n = 36
answers per arm, model `gpt-4o-mini`, graded deterministically — no LLM judge, same rule for
every arm, and the grader never saw which tool produced the answer.

| | shell (ripgrep) | ctx-optimize | graphify |
|---|---|---|---|
| Overall correctness | 35% | **67%** | 40% |
| Tool calls per run | 42.7 | **15.0** | 26.0 |

[The full scoreboard, question by question →](/ctx-optimize/benchmarks/#1-answer-quality--the-graded-agent-run) ·
[gather, query and store size against other tools →](/ctx-optimize/compare/)

## What a citation is worth

A recorded transcript, both arms asked *which functions call `requestWithVars`*. It is here
because it shows the mechanism the two rows above are made of: grep returns lines, so the
agent has to name callers it never saw.

<Tabs>
<TabItem label="shell + ripgrep — 0/2">
```text
$ grep -r 'requestWithVars' .        → 189 bytes of matching LINES

The functions that call `requestWithVars` are:
 1. In `mux.go` at line 4: `req = requestWithVars(req, match.Vars)`
 2. In `test_helpers.go` at line 3: `return requestWithVars(r, val)`

✗ no caller named · line numbers are grep's own output positions
```
</TabItem>
<TabItem label="ctx-optimize — 2/2">
```text
$ ctx-optimize affected requestWithVars

The following functions call `requestWithVars`:
 1. Router.ServeHTTP    — mux.go, lines 188-229
 2. SetURLVars          — test_helpers.go, lines 17-19
 3. ExampleSetURLVars   — mux_test.go, lines 2549-2556

✓ one call · resolved symbols · real ranges
```
</TabItem>
</Tabs>

## The external surface

`boundaries` answers what direction a call goes, over what transport, and whether a name is a
credential. On this repo, with rows elided to fit:

```text
$ ctx-optimize boundaries
boundaries: 73 ports

CONSUMES (what this system calls out to)
  config.env     28 · 28 external · 1 SENSITIVE · 3 dynamic
      OPENROUTER_API_KEY                 INFERRED   SECRET  proof/agent/agent.mjs:L28 (+1 sites)
      … 27 more not shown — --all for the full list
  network.http   16 · 16 external
      api.github.com                     INFERRED    internal/app/app.go:L3149

UNRESOLVED  3 ports carry a dynamic identifier — the SITE is certain,
            the value is not
```

Credentials are flagged by name; a value never enters the graph, is never printed and is
never stored. [How it works, and its two limits →](/ctx-optimize/boundaries/)

## Where we lose

ripgrep is faster per call than we are, CodeGraph is faster still on kernel queries, and grep
beats us outright on "where is X" — 47% to our 42%.
